# Real-Project Failure Distillation Boundary

rule_id: real_project_failure_distillation_boundary
evidence_level: internal-governance-with-regression
last_checked: 2026-07-31
importance: important_knowledge

An observed real-project failure may improve the public mainline only after it is reduced to a generic, independently reproducible mechanism.

The original evidence stays in its authorized workspace. Public artifacts may contain the failure category, observed-versus-inferred split, generic reproduction, source-backed correction, claim boundary, and focused regression. They must not contain project identity, location, private asset/task/bucket identifiers, unpublished settings or metrics, credentials, private links, or clues used to reconstruct omitted context.

An important lesson must name an existing rule, failure card, data contract, planner/validator implication, or claim boundary and must have a regression. A successful repair proves only the scoped mechanism checked by that regression; it does not transfer project results or scientific validity.
